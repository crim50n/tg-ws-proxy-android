# TG WS Proxy 2.1.0

## New Transports

- HTTP/2 media fallback over shared Cloudflare connections, with bounded buffering, request recovery and cancellation when the network changes.
- Optional Cloudflare Worker routes, tried before regular Cloudflare/TCP fallback.
- Multiple custom Cloudflare domains.
- Optional inbound Fake TLS with `ee` proxy links, handshake masking and replay protection.
- Advanced options for Cloudflare port-80 transport, PROXY protocol v1 and Telegram test data centers.
- Adapted from Flowseal/tg-ws-proxy commit `6690b788432fd0f59b0f38e228494bcd6bede1ca`.

## Settings and Reliability

- New settings are grouped with local proxy, Cloudflare and data-center options, with English and Russian descriptions.
- Worker and protocol options remain accessible in automatic mode. HTTP/2 controls reflect Cloudflare, TLS and test-DC requirements.
- Automatic mode continues to manage routing defaults and react to Android network changes; saved manual route choices apply when it is disabled.
- Fixed WebSocket shutdown after remote EOF, stale HTTP/2 lane cleanup and cancellation races.
- Recovery can rotate stalled HTTP/2 requests without interrupting response bodies.
- Fake TLS replay detection also rejects timestamp-only modifications of an accepted handshake.
- Existing power-saving defaults are preserved; Worker connections open on demand.

After enabling or changing Fake TLS, add the updated proxy link in Telegram.
PROXY protocol is only for listeners behind a compatible L4 proxy; leave it off for direct Telegram connections.

## Verification and Limits

- 237 JVM tests passed before release preparation. Settings were inspected on an Android emulator in English and Russian, light and dark themes, and automatic/manual modes.
- Real Telegram interoperability and network handover with the new transports still require device validation.
- Transport certificate verification remains intentionally disabled. Optional port-80 transport adds no TLS; Fake TLS camouflage is not an additional encryption layer.
